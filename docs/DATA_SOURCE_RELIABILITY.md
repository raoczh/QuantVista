# 免费数据源稳定性说明

本轮目标：让单个免费接口失败时，仍尽可能获得**口径正确、来源可查**的数据，而不是把更多库名当成更多独立供应商。调研及本地接口核验日期为 2026-11-02；不包含生产服务器验收，也不承诺免费接口长期可用。

2026-11-03 针对部署后反馈的热力图、数据健康和补采故障，补充了板块独立备用、日历/维护预检查、日线时效和研究消费修复，详见 [取数链路复核](DATA_PIPELINE_REVIEW.md)。下方保留上一轮网络核验记录，不代表当前所有来源均可用。

## 1. 默认接入的主备能力

- **实时报价**：东财 → 腾讯 → 新浪。保留原始数据时间，报价过期时在总预算内继续寻找更新数据；没找到时允许返回最新旧候选，但仍标记旧数据。
- **前复权股票日线**：东财 `push2his` 的 `fqt=1` → 腾讯 `web.ifzq.gtimg.cn/appstock/app/fqkline/get` 的 `qfqday`。在线分析、历史初始化、除权重锚共用路由。腾讯原始 `day` 不替代股票前复权数据。
- **行业/概念热力图**：东财 → 新浪的独立分类汇总。新浪行业使用 `newSinaHy.php`，概念使用 `newFLJK.php?param=class`；保留 `sina:new_*` / `sina:gn_*` 标识，不转换成 BK 码。市场行业榜同样可回退新浪。成员列表再补一次带日期的批量报价；板块汇总未提供统一时间、涨跌家数时明确保持未知。
- **指数、基准与已发生交易日**：腾讯 → 新浪。上证指数明确使用 `sh000001`，不经股票代码映射，避免误取深市平安银行。腾讯日线请求最大 640 根；不足不伪造，不把未知未来工作日写成已开市或休市。
- **全市场当日快照**：东财 → 新浪。新浪先使用 `Market_Center.getHQNodeStockCount` 与按代码排序的 `getHQNodeData` 枚举，再分批从 `hq.sinajs.cn` 取得带日期的真实量价。首尾计数、分页条数、唯一代码、报价身份及价格时间必须一致，拒收半截清单。只覆盖项目现有沪深 A 股范围。
- **5 分钟线**：腾讯 `mkline` → 新浪 `CN_MarketData.getKLineData?scale=5`。新浪返回股数，转换为项目的“手”。1 分钟分时仍只有腾讯，不能用 5 分钟数据冒充。
- **个股榜单**：东财增加 `clist` 适配，与原有新浪榜单互备；支持涨跌幅、成交额、换手率和 PB 的升降序。排序方向分别转换，不把亏损 PE 当作正盈利估值。
- **估值**：东财 `stock/get` 增加适配，与腾讯互备。`stock/get` 与 `clist` 字典不同，使用 `f162/f163/f164/f167` 解析动态/静态/TTM PE 与 PB；`f116/f117` 已是元，不套腾讯的亿元倍数。
- **公告**：东财 → 巨潮公开披露网站。用官方搜索结果查证券对应 `orgId`，再只读 POST 查询公告；核对代码、编号、日期和 PDF 路径。使用 `www.cninfo.com.cn`，不是需要 Token 的 `webapi.cninfo.com.cn`。不下载全文、不猜机构编号。
- **快讯**：财联社、东财、新浪分别采集，再按原有数据库及标题规则去重。各源有独立短预算，前一个源超时不会耗尽后续来源的时间。新浪采用 `zhibo.sina.com.cn/api/zhibo/feed`，保留原文和发布时间，不从正文猜关联股票。

这些新增能力不需要个人 API Key、购买积分、Python 环境或额外数据服务。`TUSHARE_TOKEN` 仍是历史预留变量，当前没有 Tushare 适配器，填写它不会启用备用源。

## 2. 为什么不能只“多加几个接口”

项目原来已有三种报价来源，但后台历史初始化仍直连东财，腾讯日线也尚未接入；因此“行情可以显示”不等于“历史补采可以恢复”。本轮把在线日线和后台补采接到相同的前复权回退链。

另外几类可直接从代码确认的问题也已处理：

- 无 Redis 时，旧热点缓存直接失效，图表、指标、筹码会为同一股票重复抓历史。本轮增加进程内缓存，并把常用日线读取合并为 250 日公共窗口，最后才裁剪调用方所需尾窗。
- 原有 HTTP、报表及页级嵌套重试可能把一次失败放大成更多请求。本轮常规网络重试集中在 HTTP 层，永久错误不重试，分页取消立即退出。
- 冷却中的延迟域需要到期试探恢复，不能永久粘住；失败、取消、空数据不能记成域恢复成功。
- 请求已经有长 deadline 时，也必须受在线总预算限制；否则批任务的大预算会放大单个接口的等待。
- 切换价格源后不能把 `source` 固定写成东财；缓存命中不能把采集时间当成源更新时间。

本地真实请求已复现东财主域及数字子域日线 `EOF`。改成规范主域不能解决所有远端断连，主要保护仍是独立备用源和合理请求纪律。

## 3. 请求与缓存边界

- HTTP 默认最多 3 次物理尝试、20 秒总预算、单请求 8 秒；拨号和 TLS 各 3 秒、响应头 5 秒。只重试明确可恢复的网络错误和 408/429/500/502/503/504。
- 服从 `Retry-After`，预算不足以等待完整时直接保留错误；不会截短等待或立即换域绕过。拒绝重定向、HTML 验证页、显式失败 envelope 和超过 4MiB 的响应。
- 东财、腾讯各共享并发 2、相邻放行至少 250ms；新浪行情共享并发 2、至少 500ms；巨潮并发 1、至少 500ms。东财数据中心与 F10 共享 500ms 间隔。以上是本项目的保护参数，不是上游承诺的额度。
- 东财主/延迟域各可能进行一次 HTTP helper 调用，所以一次域回退最多 6 次物理尝试，但仍共用 20 秒预算；常规 Manager 路由再限制为单源 6 秒、总计 15 秒。没有无限重试。
- 全市场快照为分页任务，单源 4 分钟、整体 8 分钟；普通后台同步任务仍有更外层的作业上限。5 分钟因子同步改为 4 个 worker，单股预算 15 秒、整轮 60 分钟，适配共享限速后的耗时。
- 东财域断路器是**适配器实例级**：连续 5 次故障熔断 2 分钟，到期单请求半开；默认 Manager 的能力健康滑窗在进程内共享，50 次窗口、至少 20 次样本后按既有错误/空响应阈值冷却 5 分钟。它们不是跨容器全局限流。
- 热点响应缓存每个 MarketService/BoardService 最多 1024 条、32MiB，单条最多 2MiB；报价 10 秒、盘中及收盘更新期日线 60 秒、其余日线 10 分钟、榜单/估值 60 秒。日线缓存按日期和交易阶段隔离，盘中半根不跨收盘复用；有数据但落后的主源会继续尝试备用。合并同键并发请求，调用方得到独立对象，所有等待者取消则取消共享取数。错误、`null` 和空数组不缓存；不把 Redis 的未知剩余时效续成新的本地 TTL。
- 已配置但故障的 Redis：缓存操作最多 250ms，失败后短路 15 秒；未配置仍为关闭 Redis，而不是把权限等业务缓存搬到本地。
- 公告成功刷新冷却 1 小时；临时失败保留错误并缩短为 1 分钟后可重试。库中已有历史公告可继续按原发布日期查看，不能解释成“已确认没有新公告”。
- 交叉核验补齐研报逐次节流、人气榜 POST 请求治理和 DC/F10 跨请求 Retry-After 冷却。纯本地限流排队、尚未发起 HTTP 的失败不算上游健康样本；探测会带 `LOCAL_SOURCE_WAIT`、样本数 0。已发起真实尝试后的超时仍计故障，空 `rc=0,data=null` 不清除东财断路器的失败记录。

## 4. 数据安全与诚实降级

**不能为可用率牺牲数据口径：**

- 新浪普通日 K 未复权，不能进入共用股票日线历史。腾讯只认 `qfqday`；字段缺失、非有限数字、冲突重复日期和不合理 OHLC 会让该源失败并切换。
- 除权或跨源价格差异触发完整历史重锚。失败保留旧完整序列，不允许半新半旧价格混接。重锚保留同日已有真实成交额和换手率，腾讯未提供的字段不估算。
- 新浪快照价格来源记为 `sina_spot`，区别于旧版不复权 `sina` 日线。未提供的行业与 TTM 首次保持缺失；同日重跑不覆盖此前已取得的值，绝不从其他交易日复制充数。
- 停牌可能保留上一成交价但开高低、成交量、成交额全零。保留其列表身份和原始报价，不伪造 OHLC，也不落当日日线。
- 时间按北京时间解析；缺失时间不回填现在，未来报价不视为新鲜。公告的落款日期可与实际页面公开时刻不同，仍原样保存，不能为了显示“今日”篡改日期。
- 缺少成交额/换手率时，依赖这些字段的因子可能仍无法完整计算。补到了价格并不等于所有指标都补齐。

## 5. 开源项目与官方资料依据

核查了源码调用关系，而不是仅摘录项目宣传页：

1. [Ashare](https://github.com/mpquant/Ashare/blob/master/Ashare.py)：腾讯日线和新浪分钟线的轻量 HTTP 路线，是本轮跨源组合的参考。实际解析、参数上限和数据校验仍以本项目的实测及契约为准。
2. [AKShare 腾讯历史](https://github.com/akfamily/akshare/blob/main/akshare/stock/quote/stock_hist_tx.py)：调用腾讯 `newfqkline`，区分 `day/qfqday/hfqday`。本项目使用另一个经过实测的 `fqkline` 入口，不假定两个入口具有相同响应。
3. [AKShare 新浪历史](https://github.com/akfamily/akshare/blob/main/akshare/stock/quote/stock_zh_a_sina.py)：完整新浪复权日线需 JS 解码和独立因子，分钟线有直接入口，源码提醒大批量重复抓取可能封 IP。本轮没有把普通新浪日线当成免费前复权替身。
4. [AKShare 公告](https://github.com/akfamily/akshare/blob/main/akshare/stock/research/stock_notice.py)：底层是东财 `np-anotice-stock`。再套一层 AKShare 并不会形成独立公告源，所以本轮增加巨潮。
5. [efinance 公共行情](https://github.com/Micro-sheep/efinance/blob/main/efinance/common/getter.py)：实时 `clist` 和历史 `kline` 同样依赖东财；不能与东财原接口算两份独立容灾能力。
6. [daily_stock_analysis 的数据适配器入口](https://github.com/ZhuLinsen/daily_stock_analysis/blob/main/data_provider/__init__.py)：声明 Efinance、AKShare、Pytdx、BaoStock、Tencent 等来源及优先级，支持按能力多源组合。其 `base.py` 本次获取失败，不把内部熔断算法写成已经核实的事实。
7. [mootdx 行情客户端](https://github.com/mootdx/mootdx/blob/master/mootdx/quotes.py) 与 [tdxpy 0.2.7 发行包](https://pypi.org/project/tdxpy/0.2.7/)：通达信 TCP 路线，需要节点、协议和连接维护；不是一个免运维 HTTP URL。已研究但未加入本轮默认部署。
8. [BaoStock 0.9.4 官方发行包](https://pypi.org/project/baostock/0.9.4/)：包内 `security/history.py`、`util/socketutil.py` 显示历史查询和 TCP 会话，公共入口为 `public-api.baostock.com:10030`。不是实时 HTTP 快照替代，也未验证当前节点、额度或全部免费权限；不为此额外引入常驻 Python 服务。
9. [巨潮公开披露](https://www.cninfo.com.cn/) 与 [新浪 7×24](https://finance.sina.com.cn/7x24/)：本轮只读查询实际返回成功；保留原文、原日期和官方附件链接。

源码链接说明调用关系，不提供数据授权或 SLA。免费个人研究与对外再分发是不同授权场景。

## 6. 验证方法与当前边界

默认测试使用合成响应、内存数据库和本机测试服务，覆盖请求取消、超时、Retry-After、超限响应、断路器恢复、共享缓存、来源落库、重锚保护、分页漏行及公告/新闻解析。不读取生产数据库，也不启动应用后台任务。

本轮已执行：

- 后端全包 `go test -p 1 ./... -skip '(?i)Live' -count=1 -timeout=12m` 通过；另行验证停牌快照的新增回归。
- `go vet -p 1 ./...`、`go build ./...` 通过。
- 前端 `npm test`、`npm run type-check` 通过；Vite 生产打包以 `write:false` 验证通过，没有覆盖已有嵌入产物。
- Playwright 对 `/admin`、`/news` 在桌面/平板/手机 × 亮/暗主题共 12 项检查通过，使用拦截 API 的合成数据。
- 当前本地 `CGO_ENABLED=0`，未运行 race detector；没有执行生产 MySQL 迁移、Docker 发布或真实交易/通知操作。

低频上游核验（在 `server/` 下，PowerShell）：

```powershell
$env:LIVE_FREE_SOURCES = '1'
go test ./datasource -run '^TestLiveFreeSources$' -count=1 -timeout=2m -v
Remove-Item Env:LIVE_FREE_SOURCES
```

这个测试会如实报出单个来源失败，即使自动回退子测试成功。2026-11-02 本地 Go 请求中：腾讯日线、新浪 5 分钟线及快讯、巨潮公告成功；东财日线返回 EOF，`daily_route` 实际回退腾讯并取得最新交易日。不能把这轮测试写成“所有免费接口全绿”。

完整快照另外门控：`LIVE_FREE_SNAPSHOT=1` 后执行 `go test ./datasource -run '^TestLiveFreeSnapshot$' -count=1 -timeout=5m -v`，不落库但需要分页请求，勿当作频繁健康检查。

完整新浪快照首次发现 `601326` 为“保留末价但全天无成交”的停牌格式；核对单股原始响应后修复兼容并补回归。再次完整请求成功：该来源列表中项目支持的沪深股票 **5,221 只**、有效成交 **5,215 只**，约 **61.67 秒**。这是对该来源列表的完整性核验，不是与交易所证券清单的独立全量对账，也不是长期覆盖率保证。

**仍有单源的内容**：财务三表/F10、东财板块指数及资金流、市场宽度、龙虎榜及部分情绪数据主要依赖东财；热力图虽已有新浪分类备用，但没有把不同定义的指数或资金流强行拼接。1 分钟分时仍依赖腾讯。未来休市日历、长期全量复权因子和免费接口 SLA 未解决。

**部署验收仍必须做**：在实际容器出网环境检查主备源；至少观察连续交易日的数据新鲜度、全市场覆盖和后台补跑日志。不要仅凭一次本地连通或任务“已开始”就认为稳定性问题全部消失。操作顺序见 [部署说明第 9 节](DEPLOYMENT.md#9-数据源升级与排障)。
