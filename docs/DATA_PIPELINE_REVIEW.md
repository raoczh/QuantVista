## 3. 管理接口和使用方法

均需管理员权限；正常页面即可操作，不需要手写 API。

| 接口 | 主要参数 | 返回/行为 |
| --- | --- | --- |
| `GET /api/admin/data-health` | `days=30/45/60`，默认 45 | 只读本地覆盖报告；`unknown` 表示依据不足，不等于无法联网 |
| `GET /api/admin/datasources` | 无 | 注册能力、最近成功/失败、冷却；GET 不主动探测 |
| `POST /api/admin/datasources/probe` | `provider/capability/market` | 指定来源的单能力探测摘要；不自动换成另一个来源来伪装成功 |
| `POST /api/admin/market/backfill-calendar` | `market/from/to/dry_run/plan_hash` | 范围全空默认近 92 个自然日；先预演，后凭 hash 执行 |
| `POST /api/admin/market/sync-bars` | 同上 | 默认近 45 个已知交易日，显式范围最多 60 交易日/92 自然日；每次最多 800 只待修复股票 |
| `POST /api/admin/market/wide-sync` | 同上 | 仅当前可获取的完整收盘日；不能作为历史快照回补接口 |
| `POST /api/admin/market/wide-init` | 无 | 显式续跑初始化并重试失败股票，返回 `job_run_id` |
| `GET /api/tasks/:id` | 作业 ID | `queued/running/success/degraded/failed/canceled`，查看实际最终结果 |

执行有正文的范围补采必须先 `dry_run=true`，再提交返回的 `from/to/plan_hash` 与 `dry_run=false`。预演只读本地，不请求上游。日历/覆盖在排队期间改变会使计划失效，应重新预演，不强行复用旧 hash。原无正文接口仍保留，但同样不能将盘中/错日快照写成完整收盘数据。

板块响应保持原数组形式，新增 `counts_available` 和可选 `member_count`。`counts_available=false` 时，`advances/declines` 的兼容数值不是可用观测。成员新增真实 `data_time`；详情的 `captured_at` 与 `data_time` 分开，零源时间保持未知。

## 7. 同轮交叉核验补充

- **同步完成不等于下游已更新**：日线补采（包括部分保存）、全市场同步和初始化会使同日内存因子失效。已在构建的旧输入不能重新覆盖新版本；系统作业在重建期间收到更新时保留一个合并的后续重建，锁等待受任务取消和超时约束。盘中日期和超过表目标日的根不进入收盘因子。
- **终态结算需要完整依据**：止盈、止损、到期冻结前，逐个核对结算窗口的市场交易日；缺线只能由同日已记录的停牌事实解释。采集缺口先补数据，不拿第一根旧收盘代替到期收益。历史已冻结结论不会自动重写。
- **快照回退发生在选源阶段**：主源非空但日期缺失、混入其他活跃交易日或不匹配补采目标时，也会尝试备用源。校验仍在任何价格/宇宙写入前完成。同步日志保存实际目标日，取消、部分完成及错误日期的日志不能阻止启动补跑。
- **发布分析前复核报价**：全部模型阶段结束后，再核对原计划与有效报价；价格已越出买入区间或时效无法确认时，不给当前建仓比例。原输入快照、研究区间和已完成历史不随价格追抬。
- **分钟完整性单独计错**：非空分钟序列缺根、缺少目标日或未能计算完整因子时，整轮保持部分完成。另一只股票成功不会替缺根标的推进成功游标；有效新增仍保存，恢复后可重试。
- **可信日历与 AI 证据**：报价不再沿用调度器的旧 MAX/工作日估计自证 fresh。跨越未知工作日时标 unknown；真实今日报价仍须通过交易时段时效校验。AI 市场/行业剥离显式旧指数、无法核验的榜单数值和错日统计；板块没有源时间时只作 unknown 分类观察。机构刷新失败保留库存与安全缺口说明，不把网络错误或代理地址送入模型；持仓建议保留 `quote_as_of`。本轮新分析策略版本为 `s3`，持仓建议提示词为 `pa6`。
- **运维结果可定位**：已执行探测保留安全 `result/code/audit_id`；非法请求、准入拒绝、审计失败不伪装成功。管理员系统任务定向链接生效，普通用户仍隔离；带确认计划的补采不提供复制旧 hash 的直接重跑，须重新预演。Compose 模板增加可选代理透传，真实配置未代为修改。
- **请求治理一致性**：研报每次物理尝试重新节流；DC/F10 共享上游 Retry-After 冷却而不重复限速；人气榜 POST 使用同一有限重试和响应保护。尚未发出 HTTP 的纯本地排队不污染源健康，探测返回 `LOCAL_SOURCE_WAIT`、样本数 0；有真实尝试后的失败仍计入。东财 `rc=0,data=null` 不视为熔断恢复成功。

仍需明确的恢复边界：

1. `wide-init` 续跑 pending 并重试 failed，不是对全部 done 股票逐日扫描历史洞的接口。`sync-bars` 面向 `stocks` 关注集合；不在其中的已完成宇宙股票内部缺口仍需要后续专门的有界恢复作业，不能宣称点击初始化已补齐全市场历史。
2. 每日不可变因子快照与已成功的发现保留原发布事实。同日补采会更新当前因子，但不会悄悄覆盖旧研究记录；此前已产生的错误历史如需更正，应另做审计与版本化修复。
3. 分钟源的完全无数据与真实停牌尚未形成全市场逐股恢复账本；健康页按日有记录的覆盖不代表当天每一只股票均完整。超过上游可回溯窗口的缺口也不能凭当前数据重建。

| 管理页优先用状态表 MAX；最近任务不含日线补采 | 日期取实际 `daily_bars`；最近任务包含 `sync_daily_bars`。数据交易日与任务时间分列，最新一根不代表全市场覆盖完整 |
| 推荐/追踪重新请求上游，忽略补好的本地长历史与量额 | 最近核验的完整收盘历史可直接复用；上游失败时读取已核验本地历史，成功写入后读回保留的同日事实。仍检查时效、根数及复权，不把旧数据标为新行情 |
| 主源新但仅几十根，就阻止完整备用源 | 同时考虑目标日期与请求长度，继续寻找完整备用；真正的新股短历史保留实际根数，不补造日期 |
| 重锚的第二次请求短而成功，可删掉原完整历史 | 删除前检查替换长度、库内最新日和本次已取得最新日；失败保留旧完整序列。新浪比例复权与其他算法切换时整段替换；零重叠不拼接 |
| 半根日线可能被持久化；升级后旧记录无法证明何时收盘采集 | 盘中根只作在线响应，15:05 前不入共用收盘历史。新增 `updated_at`；旧行不自动填升级时间，完成性未知/盘中采样列为待核验并重新补采 |
| 无宇宙状态的 ETF/在线股票丢失复权失败标记；旧行齐全时补采可能漏掉不可用历史 | 在必有的 `daily_bar_write_locks` 保存 `basis_unverified`，不把 ETF 塞进股票发现宇宙；计划及写后核验同时检查此标记，未解除时不把旧价格计为有效覆盖 |
| 一个追踪缺口导致整批及后续批次不再保存 | 单条保持不结算，其余合法结果继续写入，最后汇总更新数和失败数；页面重读已保存结果，不重复执行追踪动作 |
| 初始化仅一根也记 done；长期新股被 92 日日历上限误拦 | 初始化要求已确认截止日及核验历史；不足 250 根须有可信上市日、完整日历及逐日价格/停牌依据，不借未知日历认证旧数据 |

### 管理接口与返回口径

- `POST /api/admin/market/sync-bars` 新增可选 `scope`：`marketwide` 或 `tracked`；省略仍为旧客户端的 `tracked`，页面默认前者。范围、scope、宇宙、采用的上市日期和覆盖事实都参与 `plan_hash`。
- `marketwide` 默认/最大 250 个交易日，最多 400 个自然日；`tracked` 默认 45 个交易日，显式最多 60 个交易日/92 个自然日。所有范围最多回看 400 个自然日。
- 每轮最多修复 800 只；先筛待修复股票，不固定扫完整前缀。预演最多检查本地 7000 只，分批查覆盖；不会联网发现全市场股票。
- `universe_count` 表示本地已知集合大小，`target_count` 是本轮股票数；`missing_count` 包含缺失、完成性待核验或复权基准不可用的股票交易日，**不是所有日线行数**。`capped=true` 表示还有其他标的，结束后重新预演下一轮。
- `POST /api/admin/market/backfill-calendar` 日期全空默认近 400 自然日，含今天；显式范围也最多 400 日。只采用上游已发生交易日及确定的休市事实，不猜未来工作日。
- API 请求仍需管理员、预演及 hash 确认。计划变动必须重新预演；不新增付费参数、Token 或 Python 服务。

### 部署与恢复

1. 备份完整数据库及 `ENCRYPTION_KEY`，正常构建并部署新镜像。自动迁移增加 `daily_bars.updated_at/amount_source/turnover_source` 与 `daily_bar_write_locks.basis_unverified`；不要手工删除旧行或改时间戳。
2. 探测腾讯/新浪 `daily_bars`、搜狐 `daily_facts`。搜狐只有量额事实能力，不作为价格备用；某个来源失败不等于整个路由失败。
3. 日期留空先回填日历。若尚无全市场清单，盘后执行全市场增量同步；再用默认全市场范围执行日线补采。已标 done 但缺日或待核验的股票也会进入计划。
4. 查看任务最终状态及“实际核验保存/剩余”，重新预演直到无其他待修复标的。新股上市日前日期仅凭可信事实排除；没有停牌证据的缺日仍需处理，不能强写成功。
5. 等待因子重建，再刷新追踪或新建推荐。历史推荐正文、不可变因子快照和已冻结终态不重写；历史质量警告仍保留生成当时的事实。
