## 0. 结论先行

QuantVista 当前已不是一个“缺少基础功能的股票分析 Demo”。与这 50 个仓库逐项核对后，它在以下方面已经处于样本中的较高完成度：A 股免费多源行情、数据新鲜度与故障降级、基本面/资金面/新闻/公告/机构观点、条件树选股、真实约束回测、推荐后验评估、持仓账本与模拟盘、LLM 结构化契约、证据核验、提示词实验和审计。后续不应重写现有主链路，也不应为了“功能数量”照搬多智能体框架、桌面端或自动交易。

真正值得投入的增量集中在八条主线，其中第一条应优先于继续堆研究功能：

1. **个人散户日常操作收口**：首页先展示“今天与我有关的事”，全局搜索支持名称/拼音/代码，个股操作不重复输代码，复杂页面默认先给结论，手机端保留 5 个高频入口。
2. **统一任务与作业中心**：把现有“后台任务 + 页面轮询”深化为阶段进度、取消、失败重跑、批量任务和作业历史。
3. **组合风险中心**：在现有持仓账本与资产曲线上补齐多组合、相关性、波动、Beta、回撤、风险贡献、压力测试和再平衡建议。
4. **基金与 ETF 研究中心**：从当前 ETF 行情/模拟交易扩展到基金经理、4433、ETF/基金持仓穿透、重仓重叠、股票反查基金。
5. **市场宽度与轮动工作台**：补齐 ADL/ADR、RPS、行业拥挤度、资金/换手拥挤、主线/异动/退潮分类，以及指数分时上的板块事件标记。
6. **策略与因子实验室**：在已有条件树、RankIC、walk-forward 上补齐策略版本、组合策略、权重/事件回测、因子分层收益、换手与参数稳健性分析。
7. **报告与研究工件中心**：补齐报告日历、搜索/收藏/版本对比、批量分析、Markdown/JSON/Excel/PDF 导出和可复核证据包。
8. **运营可观测性**：把现有数据源健康、LLM 审计、异步任务和定时作业做成统一运维视图，并增加用户可见的 token/成本统计。

其中最优先的不是“新增一个页面”，而是增强已有能力的可操作性。例如 QuantVista 已有提醒，但缺少复合规则和可视化编排；已有后台 LLM 任务，但缺少阶段进度、取消与重试；已有持仓总览，但缺少真正的组合风险指标；已有板块热力图，但缺少宽度、RPS 与轮动状态。

### 0.1 给个人散户看的结论

如果不看后面的工程术语，这份规划最终要解决的是下面六件事：

1. 打开应用先看到“我的持仓和自选今天有什么事”，而不是先面对一堆市场模块；
2. 输入“茅台”“mt”或“600519”都能找到股票，查到后直接加自选、设提醒、分析或记一笔持仓；
3. 个股页先用一屏说清“发生了什么、为什么值得看、风险在哪”，想深挖再展开指标和原始证据；
4. 提醒优先提供“跌破我的成本、盈利回撤、财报临近、解禁临近”等模板，不要求用户先学会技术指标；
5. AI 分析和日报可以放到后台跑，离开页面后仍能从“最近任务”找到结果和失败原因；
6. 手机上用底部 5 个入口完成首页、自选、待办、持仓和搜索，常用操作不藏在多层抽屉里。

因此，新增功能之前应先完成第 5 章的散户体验专项。它大多复用现有页面和数据，成本低于新建基金、因子或多市场中心，却会更直接地改善每天的使用感受。

## 5. 个人散户体验与操作优化专项

前面几章回答“系统还能做什么”，这一章只回答“个人散户能不能每天轻松用”。个人自用产品不应要求用户先理解模块边界、因子名或任务状态；应围绕“我今天该看什么、这只股票怎么了、我的持仓要不要处理”组织操作。

QuantVista 并非从零开始。`Home.vue` 已有个人概览和个股速查，`GlobalSearch.vue` 已有 `Ctrl/Cmd+K`，自选/持仓能深链到分析、提醒和问答，`Today.vue` 已聚合待办与事件日历，持仓账本支持分批交易和部分撤销，`FreshnessTag/TrustBadges` 能说明数据时效与证据。应保留这些底座，重点减少入口、重复输入和默认展示量。已有散户功能的实现状态仍以 [RETAIL_EXPERIENCE_PLAN.md](./RETAIL_EXPERIENCE_PLAN.md) 为准。

### 5.1 用户一天的理想路径

| 时刻/任务 | 进入后先看到什么 | 最短操作路径 | 不应该发生 |
|---|---|---|---|
| 首次使用 | 三个通俗问题：偏短线还是长线、能接受多大波动、关注价位范围 | 选偏好→导入/添加第一只自选或持仓→选择是否开提醒；全部可跳过，3 分钟内完成 | 首屏要求配置模型、Webhook、因子或 Cron |
| 盘前 | 与持仓/自选有关的财报、解禁、除权、昨夜公告和待处理提醒 | 首页“与我有关”→点一项看证据→设提醒或记计划 | 先翻市场快讯再自己判断哪些与我有关 |

### 5.5 体验验收标准

1. 新用户不配置 LLM 高级项也能在 3 分钟内完成第一只自选或第一笔持仓；引导可跳过且不会反复弹出。
2. 任意页面按名称、拼音首字母或代码找到股票并进入详情不超过 2 次主要操作。
3. 从自选、持仓、推荐、提醒进入其他股票功能时，不需要再次输入市场和代码。
4. 从列表进入详情再返回，原筛选、页签、展开状态和滚动位置仍在。
5. 一条提醒推送最多 1 次点击回到触发股票和证据；过期登录恢复后仍回原目标。
6. 后台任务离开发起页不会丢失；从任何页面不超过 2 次操作能找到状态、结果、失败原因和重试入口。
7. 个股、推荐和 AI 结果的第一屏不出现大段原始 JSON/模型原文；主要结论、风险、时点和下一步无需滚动即可看到。
8. 375×812 手机视口无横向溢出；核心按钮不被底栏或软键盘遮挡；图表能全屏查看。
9. 数据过期、部分缺失和加载失败都有明确状态与恢复动作；旧数据不会伪装成实时数据，错误也不会清空用户刚填的表单。
10. 删除、批量移动、导入、账本修正等高影响操作有确认和结果摘要；可恢复的操作提供撤销，不可恢复时明确说明。
11. 涨跌、风险和状态不只依赖颜色；键盘焦点、字号放大和读屏标签覆盖高频入口。
12. 至少用 5 个真实任务做人工可用性测试：添加自选、设置成本止损、记录一次减仓、找到财报事件、从失败任务恢复；每次记录耗时、误点和卡点再迭代。

## 6. 实施路线与优先级

### 6.1 排序原则

优先级不是按参考仓库 Stars，也不是按页面数量。排序使用以下标准：

1. 是否直接改善 QuantVista 的日常研究闭环；
2. 是否复用现有数据、模型和 UI，而不是引入第二套系统；
3. 是否能提高准确性、可复现性、风险控制或操作效率；
4. 是否有清晰的自动化验收与回滚边界；
5. 是否会增加数据授权、LLM 成本、合规或运维负担。

| 可编程插件 | 条件树确实无法表达高价值策略、沙箱和资源限制可验证 | 禁止任意 Python/Go 解释执行 |

## 7. 推荐的目标架构

### 7.1 保持单体，增加工件化边界

不引入微服务。推荐仍采用 Go 单体 + MySQL/SQLite + 可选 Redis，新增能力围绕“任务、数据集、策略、报告、组合”五类工件展开：

```text
数据源适配器
  -> 标准化/质量门
  -> point-in-time 数据与快照
  -> 因子/事件/组合计算
  -> 任务步骤与报告工件
  -> Web 页面 / 通知 / 只读外部接口
```

Python 只允许用于离线模型训练、PDF 解析试验或一次性研究；产出必须冻结成带 schema/version/hash 的工件，由 Go 在线加载。禁止线上关键请求依赖一个不可审计的 Python 服务。

### 7.2 建议新增或演进的数据模型

| 模型 | 关键字段 | 设计约束 |
|---|---|---|
| `JobRun`（P0-2B-2B 已落地） | 含 kind、owner/user_id/triggered_by、status、request_hash、trace_id、parent_id、cancel_requested、error_code、result_type/result_id；七类用户任务与六类 system 任务已接 | in-flight 幂等键；终态不可回退；列表与指标不读请求或大结果；system 的 user_id 必须为 SQL NULL |
| `JobStep`（P0-2B-2A 已落） | 含 run_id、sequence、name、status、started/finished、error；通用四类、分析、推荐、日报各有真实步骤 | 步骤字典按 job kind 版本化；只记录事实，不伪造百分比 |
| `ResearchArtifact`（P0-2B-2B 一期已落地） | type、schema_version、subject、as_of、available_at、content_hash、source_refs、storage_ref、job_run_id、owner/user_id、created_at | 只为新生成且已持久化的分析、推荐、日报建立不可变幂等索引；不复制正文/候选池/快照，不猜测回填历史；回测/PDF/导出仍是后续 |
| `ScreenerStrategyRevision`（P0-4A 已落地）/通用 `StrategyRevision`（后续） | 当前模型含 strategy_id、user_id、revision、完整快照、hash、created_at；通用层再补 parent/status/created_by | 当前采用线性 revision + 主表当前指针，应用层首写不可变；扫描/回测结果尚未持久化并接 Artifact，不得把一期模型夸写成所有策略类型均已版本化 |
| `PortfolioAccount` | user_id、name、kind、currency、is_default、status | 现有持仓迁移到默认账户；一个持仓只能属于一个账户 |
| `MarketBreadthSnapshot` | trade_date、universe_version、ADL/ADR/RPS/拥挤分量、coverage | 每日首写胜；分量与综合状态同时保存 |
| `EventCluster` | fingerprint、first/last_seen、canonical_item、members、sources、status | 自动聚类可人工修正；修改留审计 |
| `Fund/FundHolding/FundManager` | report_period、announcement_date、available_at、source、holdings | 披露滞后是模型的一部分，不得只存“最新” |

不建议新建平行的行情、持仓或 LLM 调用表。上述模型应引用现有 `daily_bars`、`positions/position_trades`、`llm_call_logs` 和业务记录。

### 7.3 API 设计原则

- 查询 API 默认分页、按用户隔离，详情才读取大正文；
- 异步创建返回 `202/processing + run_id`，重复请求命中在途幂等键；
- SSE 只传状态事件和轻量摘要，完整结果仍走详情 API；
- 导入 API 必须“上传→预检→预览→确认→结果/回滚”，不能上传即改账；
- 报告/策略/数据集 API 必带 `schema_version`、`as_of`、`content_hash`；
- 管理操作全部限流并写操作审计；
- MCP 或外部 API 若立项，复用服务层和权限，不旁路 JWT/审计/信任层。

### 7.4 前端信息架构

个人散户版不再增加一级菜单。桌面一级导航收敛为“首页、今日、自选、选股、持仓”，全局搜索始终可见；手机底栏固定“首页、自选、搜索、待办、持仓”。现有路由可以保留，入口按任务归组：

| 承载位置 | 聚合内容 | 入口方式 |
|---|---|---|
| 顶栏“最近任务” | 我的分析/推荐/报告/导入/批量任务，进度、重试和结果 | 顶栏状态按钮显示最近 3 项；完整历史归“研究→任务” |
| 研究 | AI 分析、日报/报告、问答、对比、推荐追踪、任务历史 | 桌面二级菜单；从股票或首页深链直达具体任务，不要求先进入中心页 |
| 持仓 | 持仓编辑、流水、复盘、多组合、收益风险、暴露、压力测试和再平衡草案 | 持仓页内部页签；风险能力不新增一级入口 |
| 市场 | 情绪、快讯、热力图、宽度、RPS、轮动和指数事件 | 首页第二层或“市场”二级菜单，不为每个指标单开页面 |
| 用户菜单→管理后台 | 定时作业、数据源能力、缺口、成本和审计 | 仅管理员可见，不与个人研究入口混排 |

基金研究立项后先归“选股/研究”的二级入口；只有使用频率证明它属于日常主路径，才评估是否提升为一级入口。路由数量可以多，但用户每天需要理解的入口必须少。

## 8. 验收标准与防回归门

### 8.1 全局验收门

所有新增或增强能力必须同时满足：

1. **时间正确**：训练、回测和历史分析只消费 `available_at <= as_of` 的数据；
2. **口径唯一**：回测、推荐追踪、模拟盘和组合计算复用同一费税/执行/交易日语义；
3. **缺失诚实**：缺失、过期、部分覆盖和真正的零值严格区分；
4. **版本可复现**：策略、prompt、数据集、模型、报告 schema 和任务输入均可回放；
5. **失败可观察**：错误码、失败阶段、是否可重试、降级结果和上游来源可查；
6. **用户隔离**：任务、组合、报告、导入批次和成本数据按用户隔离；
7. **成本有界**：批量、LLM、数据补采和导出都有并发、时间、行数、token/文件大小上限；
8. **安全不回退**：SSRF、密钥加密、JWT、限流、LLM 契约和调用审计不得被插件/Agent 绕过；
9. **许可证清晰**：无许可证、GPL/AGPL 项目不复制源码；依赖进入前更新 SBOM；
10. **合规表述**：仍使用研究观察、候选、计划和风险语言，不输出确定性收益承诺或自动交易指令。

### 8.2 关键工作包的可量化验收

| 工作包 | 最小验收（自动化 + 必要目验） |
|---|---|
| 散户高频路径 | Playwright 覆盖名称/拼音/代码搜索、股票上下文深链、返回保留现场、提醒模板、后台任务找回和 375×812 手机底栏；再用 §5.5 的 5 个真实任务做人工目验 |
| 任务中心 | 同请求防重、多用户隔离、取消竞态、失败重试 parent 关联、SSE 断线恢复、终态幂等、列表不加载正文 |
| 市场宽度 | 用固定行情 fixture 手算 ADL/ADR/RPS；股票宇宙变化不重写历史；缺失率进入 coverage |
| 组合风险 | 用小型价格矩阵手算 TWR/Beta/波动/回撤/相关；partial 快照剔除；多币种未支持时明确拒绝 |
| 策略版本 | A→B→A 仍产生新 revision；旧回测引用旧 hash；删除只能归档，不能破坏历史外键 |
| 批量分析 | 单股超时/失败不影响其他项；并发上限生效；预算耗尽停止排队项；结果逐项可追溯 |
| 复合提醒 | all/any/not、窗口边界、同日去重、静默/升级、命中快照、复杂度上限和后台锁等待测试 |
| 报告导出 | Markdown/JSON 与数据库字段一致；PDF 字体/分页；恶意 Markdown/CSV 公式/路径穿越防护；导出权限隔离 |
| 基金持仓 | report_period/announcement_date/available_at 对拍；重叠率手算；过期持仓醒目标记 |
| PDF 证据 | 页码/段落/哈希可回原文；OCR 失败为 unknown；prompt injection 文本被视为不可信数据 |
| 作业/数据运维 | 手动探测限流、解冷审计、补采日期上限、失败游标推进策略、上游空响应和字段漂移 fixture |

## 9. 明确不借鉴与需谨慎借鉴

| 项目方向 | 结论 | 原因 |
|---|---|---|
| 微服务、gRPC、多节点 Agent、Mongo/Milvus 全家桶 | 不借鉴 | 个人自用规模不需要，增加部署、备份、一致性和排障成本；当前 Go 单体边界清晰 |
| 自动实盘交易、LLM 下单 | 不借鉴 | 合规、安全、误操作与模型幻觉风险远高于收益；QuantVista 定位是研究与计划 |
| Wails/Tauri/PyQt/WPF/Qt 独立桌面端 | 不借鉴 | Web + Capacitor 已覆盖跨端；重复维护 UI 和业务逻辑不划算 |
| 前端 BYOK/明文 API Key | 不借鉴 | 当前服务端 AES-GCM 和权限模型更安全 |
| 任意 Python/Go/IronPython/Yaegi 策略执行 | 不借鉴实现，仅借插件思想 | 无法有效沙箱，存在文件、网络、密钥和资源滥用风险 |
| 黑箱“综合强度/情绪指数”直接进推荐 | 谨慎 | 只能在分量透明、样本外验证、校准和版本化后作为一个因子，不能替代证据链 |
| LSTM/CNN/GRU 直接预测涨跌并展示买卖 | 不借鉴产品表述 | 多数参考仓库是教学/实验，缺 point-in-time、防泄漏、成本后样本外证据 |
| 只看训练准确率或单次回测最佳参数 | 不借鉴 | 选择偏差和过拟合；必须有 baseline、walk-forward、locked period 和邻域稳定性 |
| 同花顺复杂反爬/浏览器指纹绕过 | 不借鉴 | 稳定性、条款与维护成本不匹配，优先现有免费公开接口 |
| Redis/Mongo/本地文件多套结果权威 | 不借鉴 | 历史和状态容易分叉；MySQL/SQLite 继续作为业务事实权威，缓存可丢弃 |
| 把 ETF 当股票套用涨跌停/估值/费税 | 不借鉴 | 产品规则不同；现有 ETF 排除与免印花税逻辑应保持 |
| 无许可证仓库源码、GPL/AGPL 源码直接合并 | 禁止 | 产品思想可重新设计实现，代码级复制需单独法律审查；默认不复制 |
| 为每个参考功能增加一级菜单 | 不借鉴 | 会破坏研究工作流和扫描效率；优先增强现有页面与聚合中心 |
