# QuantVista

[![License](https://img.shields.io/badge/License-Apache_2.0-blue.svg)](LICENSE)
![Go](https://img.shields.io/badge/Go-1.25-00ADD8?logo=go&logoColor=white)
![Vue](https://img.shields.io/badge/Vue-3-4FC08D?logo=vuedotjs&logoColor=white)

QuantVista 是一个**个人自用的 AI 股票研究平台**：围绕 A 股行情数据、新闻情绪、AI 分析与推荐、持仓与模拟盘，形成可复盘、可追踪、可配置的一站式研究工作台。

系统不输出「买入答案」，而是输出**研究观察与交易计划**——给出数据依据、逻辑、风险与跟踪条件；每个 AI 结论都绑定数据快照、经过程序化证据核验，数据过期或缺失时**宁可拒答不编造**，决策由用户自行承担。

AI 链路的工程方法综合了对 UZI-Skill、TradingAgents、Superpowers、Financial Services 等 **26 个开源项目/Skill 的三轮源码调研**，把经验证的数据契约、角色纪律、证据链与评测方法固化为一条**可回放、可拒答、可测量**的中文提示词与校验体系（权威计划见 [LLM 交互准确性优化计划](docs/LLM_ACCURACY_OPTIMIZATION_PLAN.md)）。

代码规模：后端 Go 约 9 万行 + 4.9 万行测试（1100+ 测试函数），前端 Vue/TS 约 4.7 万行，38 个页面、237 个 API 路由、105 张数据表，单容器 `go:embed` 部署。

## ✨ 功能特性

### 行情与数据

- **个人优先首页**：按盘前/盘中/盘后调整「与我有关」的信息顺序（Today 收件箱、持仓风险、行情缺口、重点自选、最近研究），市场指数/榜单/情绪保留在第二层
- **市场看板**：大盘指数、涨幅榜/成交额榜/换手榜/回调榜/低 PB 榜、板块涨跌、涨跌家数情绪、两市主力资金流向
- **个股详情**：前复权 K 线（MACD/BOLL/均线）、分时线、筹码峰分布（本地复算）、主力资金流、龙虎榜、财务摘要与 F10 三表、公告、机构观点（研报评级变动/目标价偏离/调研密度）、技术面五维评分、股息率、解禁与除权事件
- **板块热力图**：行业/概念板块热度全景 + 板块详情（指数 K 线、成分股联动、板块主力资金历史、行业估值中位数与横截面/时序分位）
- **盘面情绪**：涨跌停池、人气榜、龙虎榜日榜、市场情绪快照（每 10 分钟）
- **新闻情绪**：7×24 快讯采集（间隔 1~120 分钟可配）+ LLM 情绪增强（个股关联、利好利空、当日聚合情绪分；可总闸关闭走纯规则）
- **事件日历**：未来 N 天与我相关的解禁/除权除息/财报披露 + 全市场打新（新股与可转债申购）
- **全局搜索**：股票代码/名称/拼音搜索、最近访问、一键跳转分析/问答/加自选

### AI 研究

- **AI 分析**：五模块（个股/全市场/板块/自选/持仓）精确提示词、多角色 panel（技术/动量/风险/反方）、变化检测、回溯诊断（as-of 历史时点复盘 + 事后走势对照）、个股自动附**交易计划**（买入区间/目标价/止损/持有周期/操作清单 + 量化仓位建议）
- **个股问答**：流式回答、多轮追问复用同一数据快照、风险标志程序化解析
- **横向对比**：多标的估值/评分/技术面对照 + AI 点评
- **短线/长线推荐**：系统在 63 因子宽表发布后做一次 A 股全市场日更发现，按趋势突破/回调修复/价值红利/策略信号四通道各留 Top100、保留近 5 个交易日候选记忆；生成时按当前行情与用户偏好硬过滤、重新量化评分，LLM 仅对 Top10 精选/否决
- **策略选股**：21 个内置白话策略（短线/波段/中线，基于 **63 因子**宽表）+ 自定义条件树 + **AI 白话建策略**（自然语言解析为条件树，无法映射的表述如实提示不硬凑）
- **回测时光机**：条件树策略的历史时点选股与后续走势验证、推荐批次回验（次日开盘成交、一字板买不进、停牌/跌停顺延等 A 股真实约束）
- **收盘日报**：交易日自动生成今日复盘 + 明日短线计划 + 今日重要事件（4 步硬规则打分降噪后 LLM 只写摘要），可推送、可删除重生成
- **生成链路异步化**：分析/推荐/日报/问答/选股/回测等长耗时任务全部走独立后台作业（接口秒回 + 前端轮询），调用层真 SSE 流式优先，双层化解浏览器/反代与上游网关的 60 秒级超时；AI 上游失败自动**量化降级**（ATR 规则价位、透明标记、置信度恒低）

### AI 可信与准确性

工程细节与验收门见 [LLM 交互准确性优化计划](docs/LLM_ACCURACY_OPTIMIZATION_PLAN.md)。

- **信任层**：AI 引用的数字与数据快照逐一程序化比对，命中项带证据 ID/字段路径/来源/as_of；缺失数据以结构化 unknowns 喂给模型并在前端透出「数据缺口」；置信度由程序合成而非模型自评
- **不可覆盖准确性契约**：全部业务 LLM 调用出口注入硬规则（只用快照内数据、禁编造/禁越界/禁自算指标、缺失输出 unknown、外部文本视为不可信数据）；结构化调用低温钳制、repair 轮温度归零；自定义 prompt 模板只能注入任务段
- **fail-closed 完整性门禁**：流式/整包响应的截断、内容过滤、异常终态一律拒收不落库；行情过期、无历史快照、休市、配额用尽等拒答原因全部机读错误码；LLM 失败降级为量化观察或拒答，绝不降级为无证据结论
- **claims/evidence 输出契约**：结论拆为 claim（事实/推断分栏）+ evidence_refs + invalidators（失效条件）+ watch_items（跟踪项），矛盾与未知显式呈现
- **跨模块语义校验**：风险闸门 block 时评级不得看多、短线 buy 盈亏比不足自动降观察、交易计划价位关系服务端硬校验；仓位/盈亏比等可确定性计算的量一律由程序完成
- **能力矩阵与输出预算**：每个 provider/model/端点的 JSON mode、温度、token 参数、思考档位能力由内置声明 + 运行时观察合并，已知不支持的直接声明化路由；19 个业务模块统一声明输出预算与 repair 上限
- **全链路可追溯**：trace/run ID 串联主调、repair、复核与降级，每次运行落 manifest（prompt/数据 hash、结构化方法、attempt/repair 计数、规范化终态）；prompt 模板带内容 hash 与不可变修订快照
- **推荐 coverage 诊断**：LLM 推荐输出逐条程序化归类（池内/越池/未知/重复/超量），疑似训练记忆的池外代码一律剥除，全越池自动 repair，仍失败走量化降级

### AI 提示词工程与评测

- **五层提示词架构**：L0 不可覆盖准确性契约 → L1 模块契约（字段白名单/允许动作/schema）→ L2 程序冻结数据区 → L3 用户自定义任务段 → L4 输出要求。用户模板只能调整关注角度与表达风格，时间边界、候选边界与输出纪律恒由系统追加；存量「整段替换」模板已降级为任务段注入
- **自定义模板管理**：9 个可自定义模块（个股/全市场/板块/自选/持仓分析 + 推荐/收盘日报/个股问答/AI 复核）各自编辑并启用，展示该模块默认任务段与不可覆盖的契约段供参照、支持重置为默认，模板内可用 `{market}`/`{symbol}`/`{strategy}`/`{date}` 等按模块声明的占位符（未提供值时保留原样）；每次保存落不可变修订快照与内容 hash，历史版本可回查当时模板原文
- **19 个角色资产 registry**：代码里真实接线的每个角色（论点分析师、交易计划员、分析/推荐复核员、反方研究员、候选精选器、收盘复盘员、证据问答员、对比点评员、新闻情绪标注员、白话建策略解析器、辩论四角色、反思记忆生成器、challenger 影子研究员、发布审计员、持仓风控顾问）都登记提示词版本、schema 版本、输出预算、校验点与**适用性触发条件**，版本锚用常量引用编译期绑定，锁定测试保证声明与代码一致——不登记代码里不存在的角色
- **条件式触发不是默认全开**：每个角色的触发条件都由程序判定并写进 registry，例如辩论仅在低置信度/证据冲突/风险闸门 warn 时启动（block 排除，语义校验已硬约束）、反驳轮仅在多空引用同一 evidence_id 时才给、反方只对 `action=buy` 条目、交易计划遇评级偏空或行情非 fresh 零调用。高置信度默认单路，零额外成本
- **独立多空对抗复核**：bull/bear 逐条互驳并引用证据 ID、主动给出己方失效条件；judge 按来源层级与证据强弱裁决而非票数平均；claim ID 由程序重编号不信模型自报，越界的 evidence_id 与非法 claim 引用一律剥除；辩论轮上限硬钳制、调用预算最多 4 次，任一角色失败整体降级为单路并记 `degraded_reason`
- **注入与越界防护**：外部文本（新闻标题、公告正文）恒作为数据段而非指令，带指令的内容只被引用不被执行；窗口外新闻 0 注入；自定义模板无法覆盖安全层——三类都有专门的 golden 反例测试锁定
- **回归集与发布治理**：每个角色资产配 known-answer（固定输入→精确断言）与 edge-case（失败降级/剥除/拒绝/flag 关）用例，程序校验每角色 ≥2 + ≥1 的满额门槛并检查测试函数真实存在；`llm_golden_test.go` 作为回归集目录索引全部锁定场景；champion/challenger 影子实验单变量对照（同批次、同候选、同模型，仅任务段不同），promote 需过样本量/结构化有效率/无增量不晋级等程序硬门 + LLM 发布审计员工件 + 管理员显式审批，可一键切回 champion
- **评估时间切分纪律**：联合评估按信号日切早段 dev（自由查看）与末段 locked test（默认不出指标，显式请求才计算且每次读取登记审计），不随机打散；反思记忆按 `available_from` 过滤杜绝未来信息泄漏
- **设计储备（未启用，如实声明）**：十类投资流派方法角色卡（价值质量/深度价值/GARP/护城河/宏观反身性等）与按数据覆盖自动路由方法角色，仍是文档中的设计储备，代码未接线；指标恶化自动回滚亦未实现，回滚是管理员显式动作

### 推荐准确性工程

已实现基础与后续路线见 [推荐准确性长期规划](docs/RECOMMENDATION_ACCURACY_PLAN.md)；当前施工入口见 [推荐发现与持仓卖出方案](docs/RECOMMENDATION_DISCOVERY_AND_EXIT_PLAN.md)。

- **推荐结果测准**：标签事实表按 1/5/10/20/60 日固定持有期记录扣费净收益/Alpha/MFE/MAE 与三重障碍标签；统一执行模拟器（次日开盘成交、涨停买不到、停牌/跌停顺延、T+1、整百股、费税滑点）让线上追踪、批次回验与模型验证共用同一套执行语义；用户实际成交与模型模拟并列展示不混算
- **Point-in-time 数据地板**：不复权 OHLCV + 每日复权因子防历史重锚；财务/公告/解禁按首次可知时间回放；历史股票宇宙按日重建（上市/退市/ST/停牌）防幸存者偏差；每日全市场因子宽表不可变快照
- **止血护栏**：大盘三档 regime 闸门（offense/neutral/defense）、目标波动仓位建议、批次组合去相关（同行业限额 + 高相关只留分高者）、执行纪律三条
- **影子运行方法论**：任何改变信号的门控/复核/记忆机制先影子运行——反事实事件账本记录被过滤/被改写/落选标的的后续影子收益，gated vs ungated 配对证明真实增量后才转正
- **反馈闭环**：确定性错误归因报表（入场特征桶 × 市场状态 × 策略 × 来源 × 行业）、反思记忆闭环（标签成熟触发三问反思、available_from 防历史泄漏）、独立反方研究员逐票构建 A 股 bear case、数据质量门控按策略分场景封顶置信度
- **召回评估与每日复盘**：候选池 Recall@K、逐路来源消融、错失机会率；每天以相邻有效交易日审计漏选强势机会、误选、漏斗主因与来源通道漏选率
- **评估报表**：因子 RankIC/ICIR 排行、walk-forward 滚动切分基线、固定持有期配对评估、概率校准（Brier/ECE/可靠性曲线）、组合/回测联合评估（dev 段自由查看、locked test 段显式请求且登记审计）、champion/challenger 影子实验与发布门

### 跟踪与交易

- **推荐追踪**：止盈/止损盘中触达判定、相对上证的超额收益 alpha、7/14/30 日节点收益、胜率统计、复盘待办与已读消项
- **提醒与待办**：11 类条件提醒（到价/异动/均线/突破/放量/振幅/财报临近/新业绩预告/成本止盈/成本止损/峰值回撤），四步模板向导创建，特殊组合保留专家模式；Today 统一收件箱按需处理/仅知晓/已完成聚合提醒命中、复盘信号、逻辑卡到期，支持稍后、同日静默、同股同类合并、来源筛选与批量操作
- **持仓管理**：多组合账户、多笔流水账本与加权成本/已实现盈亏、持仓期最高价与回撤、除权除息调整待确认（程序不静默改写账本，一键确认可撤销）、资产曲线、交易复盘统计（用户执行口径，不与模型口径混算）、推荐↔持仓血缘
- **持仓卖出决策**：统一卖出风险评估逐笔结合成本、计划、峰值回撤、均线/ATR/行情状态输出正常/关注/复核/紧急/未知；利空事件触发卖出复核；可发起 **AI 逐笔建议**（hold/trim/exit + 理由 + 失效条件，数值全部由程序算好喂入）
- **组合风险中心**：年化波动/下行波动/Sharpe/Sortino/Beta/Jensen Alpha/最大回撤、成分风险贡献、行业与风格暴露（缺数据如实缺席不摊派）、现金流账本与冲正、压力测试情景、目标配置修订与再平衡草案
- **模拟交易**：虚拟 10 万本金、真实行情成交与费税（佣金万 2.5 最低 5 元 + 卖出印花税万 5，ETF 免印花税）
- **指数 ETF**：精选宽基/行业主题/商品跨境 ETF 清单 + 实时行情富化，交易复用模拟盘
- **研究辅助**：投资逻辑卡（失效条件 + 一键体检）、投资笔记（可绑定标的形成个股时间线）、自选分组与研究阶段漏斗、CSV 数据导出
- **数据导入**：自选、持仓与交易流水支持向导式导入、预览校验、幂等提交与可审计回滚

### 系统与管理

- **LLM 配置**：多配置管理、OpenAI 兼容（`/v1/chat/completions` 与 `/v1/responses` 双端点）、上游 `/v1/models` 拉取选择或自定义模型、**思考档位（reasoning effort）可配**（空值沿用网关默认，上游拒绝自动去参降级并落能力观察）、测试连接、每用户次数配额熔断
- **LLM 回退与路由**：未配置 LLM 的用户可自动回退管理员指定配置（总闸 + 指定配置可控）；模块级模型路由（默认关闭）
- **首次使用引导**：投资偏好、第一只自选/持仓、提醒测试三步可跳过和恢复，进度按用户与版本留痕

## 🚀 快速开始

### 源码运行（开发）

要求：Go ≥ 1.25，Node.js ≥ 20（实测 v24）。

```bash
# 后端（SQL_DSN=local 使用本地 SQLite，零外部依赖）
cd server
SQL_DSN=local go run .

# 前端（另开终端）
cd web
npm install
npm run dev
```

访问 `http://localhost:5173`，首次启动会引导创建管理员账号。

测试：后端 `cd server && go test ./...`；前端 `cd web && npm run build`（含类型检查）与 `npm test`（页面契约脚本）。

### Docker 部署（生产）

```bash
docker buildx build --platform linux/amd64 -t <你的镜像名>:tag --load .
docker push <你的镜像名>:tag
```

单镜像多阶段构建（前端 → `go:embed` → alpine 单二进制），生产用 `deploy/docker-compose.example.yml` 为模板编排（MySQL + Redis + 应用），密钥经 `deploy/.env` 注入。完整流程（宝塔编排、反代与真实 IP、数据库自动迁移、备份恢复）见 [部署说明](docs/DEPLOYMENT.md)。

## ⚙️ 环境变量

| 变量                                                       | 必填     | 说明                                                                                       |
| ---------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------ |
| `SQL_DSN`                                                  | 是       | `local`/留空 = 本地 SQLite（开发）；MySQL DSN = 生产模式（触发密钥强校验）                 |
| `SESSION_SECRET`                                           | 生产必填 | JWT 签名密钥，`openssl rand -base64 36` 生成；生产环境弱值拒绝启动                         |
| `ENCRYPTION_KEY`                                           | 生产必填 | 敏感字段加密密钥（LLM API Key 等）；**备份恢复须用同一密钥**                               |
| `PORT`                                                     | 否       | 监听端口，默认 `3000`                                                                      |
| `SQLITE_PATH`                                              | 否       | SQLite 文件路径（默认程序目录）                                                            |
| `REDIS_CONN_STRING`                                        | 否       | Redis 连接串，缺省不启用缓存                                                               |
| `ALLOWED_ORIGINS`                                          | 否       | 生产 CORS 白名单，逗号分隔                                                                 |
| `TRUSTED_PROXIES`                                          | 否       | 反代场景可信代理地址（如 `172.18.0.1`），不设则不信任代理头                                |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` | 否       | Web Push 密钥对（`go run ./cmd/vapidgen` 生成）；缺省则浏览器通知仅走前台 Notification API |
| `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET`                | 否       | GitHub OAuth 首启种子，之后以管理后台配置为准                                              |
| `TUSHARE_TOKEN`                                            | 否       | Tushare Pro token（分档按需启用）                                                          |
| `DEFAULT_MARKET`                                           | 否       | 默认市场，当前仅 `cn`                                                                      |
| `DEBUG`                                                    | 否       | 调试日志，默认 `false`                                                                     |

## 🔐 安全特性

- **密钥加密落库**：LLM API Key、推送通道密钥、GitHub secret 均 AES-256-GCM 加密存储，模型字段 `json:"-"` 永不回显
- **JWT 双 token**：短期 access + 轮换 refresh，`TokenVersion` 支持单用户强制全端登出（禁用用户即时生效）
- **SSRF 防护**：LLM Base URL 与 Webhook 仅放行公网 http/https，内网地址仅管理员（或管理员所有的回退配置）可用
- **认证限流**：登录/注册/OAuth 按 IP 限流，行情与 LLM 接口分级限流；反代场景配 `TRUSTED_PROXIES` 后按真实客户端 IP
- **生产密钥 fail-fast**：连接真实 MySQL 时占位/弱密钥直接拒绝启动
- **调用审计**：全用户 LLM 调用明细（含请求/响应全文）仅管理员可见，90 天自动清理
- 备份恢复依赖同一 `ENCRYPTION_KEY`，密钥丢失则密文字段需重新录入
