![Go](https://img.shields.io/badge/Go-1.25-00ADD8?logo=go&logoColor=white)

QuantVista 是一个**个人自用的 AI 股票研究平台**：围绕 A 股行情数据、新闻情绪、AI 分析与推荐、持仓与模拟盘，形成可复盘、可追踪、可配置的一站式研究工作台。

系统不输出「买入答案」，而是输出**研究观察与交易计划**——给出数据依据、逻辑、风险与跟踪条件；每个 AI 结论都绑定数据快照、经过程序化证据核验，数据过期或缺失时**宁可拒答不编造**，决策由用户自行承担。

AI 链路的工程方法综合了对 UZI-Skill、TradingAgents、Superpowers、Financial Services 等 **26 个开源项目/Skill 的三轮源码调研**，把经验证的数据契约、角色纪律、证据链与评测方法固化为一条**可回放、可拒答、可测量**的中文提示词与校验体系（权威计划见 [LLM 交互准确性优化计划](docs/LLM_ACCURACY_OPTIMIZATION_PLAN.md)）。

## ✨ 功能特性

**行情与数据**

- 🏠 **个人优先首页**：按盘前/盘中/盘后调整“与我有关”的信息顺序，优先展示 Today 收件箱、持仓风险/行情缺口、重点自选与最近研究；市场指数、榜单和情绪完整保留在第二层
- 📈 **市场看板**：大盘指数、涨幅/成交额榜、板块涨跌、涨跌家数情绪、两市资金流向、AI 今日观点
- 🔍 **个股详情**：K 线（前复权，MACD/BOLL/均线）、筹码峰分布、主力资金流、龙虎榜、财务摘要与 F10、公告列表、机构观点（研报评级分布/目标价偏离/机构调研密度）、技术面五维评分
- 🗺️ **板块热力图**：行业/概念板块热度全景与板块详情页（指数 K 线、成分股联动、板块主力资金历史、行业估值中位数与分位）
- 📰 **新闻情绪**：7×24 快讯采集（间隔可配 1~120 分钟）+ LLM 情绪增强（个股关联、利好利空、当日聚合情绪分，可总闸关闭走纯规则）

**AI 研究**

- 🤖 **AI 分析**：五模块（个股/全市场/板块/自选/持仓）精确提示词、多角色 panel（技术/动量/风险/反方）、变化检测、回溯诊断（as-of 历史时点复盘）、个股自动附**交易计划**（买点/止盈/止损/仓位）
- 💬 **个股问答**：流式回答、多轮追问复用数据快照、风险标志程序化解析
- ⚖️ **横向对比**：多标的估值/评分/技术面对照 + AI 点评
- 🎯 **短线/长线推荐**：四阶段流水线——多源建池 → 用户硬过滤（股价区间、排除创业板/科创板等，可自定义）→ 本地量化评分（零 LLM 成本）→ LLM 仅对 Top 名单精选/否决
- ⚡ **生成链路异步化**：分析/推荐/日报/问答等长耗时 LLM 生成全部走独立后台任务（接口秒回 + 前端轮询），调用层真 SSE 流式优先，双层化解浏览器/反代与上游网关的 60 秒级超时；AI 上游失败自动**量化降级**（ATR 规则价位、透明标记、置信度恒低）
- 🧪 **策略选股**：21 个内置白话策略（短线/波段/中线，基于 **63 因子**宽表）+ 自定义条件树 + **AI 白话建策略**（自然语言解析为条件树，无法映射的表述如实提示不硬凑）
- ⏪ **回测时光机**：策略在历史时点的选股结果与后续走势验证（次日开盘成交/一字板跳过/涨跌停顺延等 A 股真实约束）

**AI 可信与准确性**（工程细节与验收门见 [LLM 交互准确性优化计划](docs/LLM_ACCURACY_OPTIMIZATION_PLAN.md)）

- 🛡️ **信任层（全 AI 链路）**：AI 引用的数字与数据快照逐一程序化比对，命中项带证据 ID/字段路径/来源/as_of；缺失数据以结构化 unknowns 喂给模型并在前端透出「数据缺口」；置信度由程序合成而非模型自评，可选 AI 复核员独立挑刺；全部 AI 产出标注所用 LLM 配置与模型
- 🔒 **不可覆盖准确性契约**：全部业务 LLM 调用出口注入硬规则（只用快照内数据、禁编造/禁越界/禁自算指标、缺失输出 unknown、外部文本视为不可信数据），结构化调用低温钳制、repair 轮温度归零；自定义 prompt 模板只能注入任务段，纪律/输出 schema/时间边界等系统契约不可覆盖
- 🚦 **fail-closed 完整性门禁**：流式/整包响应的截断、内容过滤、异常终态一律拒收不落库；行情过期、无历史快照、休市、配额用尽等拒答原因全部机读错误码；LLM 失败降级为量化观察或拒答，绝不降级为无证据结论
- 🧾 **全链路可追溯**：trace/run ID 串联主调、repair、复核与降级，每次运行落 manifest（prompt/数据 hash、结构化方法、attempt/repair 计数、规范化终态）；prompt 模板带内容 hash 与不可变修订快照，历史版本可回查当时模板原文；审计保留最终实际发送的完整请求
- ⚖️ **跨模块语义校验**：风险闸门 block 时评级不得看多、短线 buy 盈亏比不足自动降观察、交易计划价位关系服务端硬校验；仓位/盈亏比等可确定性计算的量一律由程序完成，LLM 只解释不算数
- 🎛️ **能力矩阵与输出预算**：每个 provider/model/端点的 JSON mode/温度/token 参数能力由内置声明+运行时观察合并，已知不支持的直接声明化路由；11 个业务模块统一声明输出预算与 repair 次数上限，预算超限拒收不静默当成功
- 📊 **推荐 coverage 诊断**：LLM 推荐输出逐条程序化归类（池内/越池/未知/重复/超量），带机读错误码与前端「AI 输出剥除」警示（正常批次零噪声）；疑似训练记忆的池外代码一律剥除，全越池自动 repair，仍失败走量化降级并保留量化分

**AI 提示词工程与评测**

- 📐 **五层提示词架构**：L0 不可覆盖准确性契约 → L1 模块契约（字段白名单/允许动作/schema）→ L2 程序冻结数据区 → L3 用户自定义任务段 → L4 输出要求；用户模板只能调整关注角度与表达风格，时间边界、候选边界与输出纪律恒由系统追加
- 🎭 **投资方法角色卡**：价值质量、深度价值、成长 GARP、创新护城河、宏观反身性、技术趋势、A 股游资盘口、量化因子解读、AI 瓶颈、推广风险识别十类流派角色，每张角色卡带字段白名单、必答问题与不适用条件（数据不齐直接 skip 不硬凑）；按数据覆盖与任务自动路由方法角色，宏观政策/行业事件/成本传导/技术形态专家角色按需触发
- 🐂 **独立多空对抗复核**：低置信度或证据冲突时启用 bull/bear/judge——多空双方逐条互驳并引用证据 ID、主动给出己方失效条件；judge 按来源层级与证据强弱裁决、不按角色票数平均，最多 3 轮辩论，风险闸门 block 时禁止输出 buy
- 📇 **claims/evidence 输出契约**：结论拆为 claim（事实/推断分栏）+ evidence_refs（字段路径/来源/as_of）+ invalidators（失效条件）+ watch_items（跟踪项），矛盾与未知显式呈现不得抹平；新闻按时间窗与来源对齐度分级，单源消息不得写成「市场共识」
- 🧬 **26 个开源项目源码调研沉淀**：三轮审阅 UZI-Skill、Superpowers、TradingAgents、AI Hedge Fund、Financial Services、Colleague Skill、Qlib、Promptfoo、FinGPT、AlphaSift、StockNova 等项目（源码实现 → 输入输出契约 → 失败路径 → 可迁移性），把数据契约、角色纪律、coverage 诊断与评测方法改写为本项目的中文提示词蓝图与验收门
- 🧪 **提示词评测与发布治理**：每个角色资产配 known-answer/edge-case 用例与 prompt injection/越池/窗口外反例；按交易日时间切分的 golden/holdout 回归集，champion/challenger 影子实验、feature flag 灰度与指标恶化自动回滚；反思记忆按 available_from 过滤，杜绝未来信息泄漏

**推荐准确性工程**（已实现基础与后续路线见 [推荐准确性长期规划](docs/RECOMMENDATION_ACCURACY_PLAN.md)；当前施工入口见 [推荐发现与持仓卖出方案](docs/RECOMMENDATION_DISCOVERY_AND_EXIT_PLAN.md)）

- 🎯 **推荐结果测准**：标签事实表按 1/5/10/20/60 日固定持有期记录扣费净收益/Alpha/MFE/MAE 与三重障碍标签（止盈先触/止损先触/到期未触）；统一执行模拟器（次日开盘成交、涨停买不到、停牌/跌停顺延、T+1、整百股、费税滑点）让线上追踪、批次回验与模型验证共用同一套执行语义；买入胜率只统计已成熟 buy 样本，watch 与未到期不混入，用户实际成交与模型模拟并列展示不混算
- 🕰️ **Point-in-time 数据地板**：不复权 OHLCV + 每日复权因子防历史重锚；财务/公告/解禁按首次可知时间回放（available_at ≤ as_of）；历史股票宇宙按日重建（上市/退市/ST/停牌/成分变更）防幸存者偏差；每日全市场因子宽表不可变快照
- 🚧 **止血护栏**：大盘三档 regime 闸门（offense/neutral/defense）、目标波动仓位建议（波动分档上限 × regime 系数 × 相关性系数、整批归一化）、批次组合去相关（同行业限额、高相关只留分高者）、执行纪律三条（buy_zone 外不追、止损一键挂提醒、T+1 首日不满仓）
- 🔬 **影子运行方法论**：任何改变信号的门控/复核/记忆机制先影子运行——反事实事件账本记录被过滤、被改写、落选标的的后续影子收益，gated vs ungated 配对证明真实增量后才转正，杜绝「少发 buy 做高表面胜率」
- 🧠 **反馈闭环**：确定性错误归因报表（入场特征桶 × 市场状态 × 策略 × 来源 × 行业）先行；反思记忆闭环（标签成熟触发三问反思、available_from 防历史泄漏、按后续验证调权淘汰）；独立反方研究员逐票构建 A 股 bear case（解禁、T+1 锁仓、高位放量、拥挤、估值）；数据质量门控按策略分场景封顶置信度
- 📏 **召回评估与 walk-forward**：候选池 Recall@K（好股票有没有进池）、逐路来源消融与错失机会率；因子 RankIC/ICIR 排行页，评分权重调整只认样本外证据；walk-forward 框架（按时间切分训练/验证/测试 + Purge/Embargo），手工评分作为 baseline 全程对照
- 🤖 **模型化排序与概率校准（规划路线）**：横截面排序按「线性/Logistic → LightGBM」演进（净收益 + Alpha 双标签，Python 离线训练、Go 只加载冻结产物）；逐模型概率校准（Brier/ECE/可靠性曲线），「不推荐」门槛以净收益硬约束优先——市场状态或数据质量不达标时 **0 推荐是正常输出**；champion/challenger 并行结算、漂移监控与退役标准，策略进化走「失败归因 → 定向变异 → 回测对比 → 人工审核」的防过拟合循环

**跟踪与交易**

- 📌 **推荐追踪**：止盈/止损盘中触达判定、相对上证的超额收益 alpha、7/14/30 日节点收益、胜率统计、复盘待办与已读消项；推荐本身不再自动生成真实持仓卖点规则
- 📋 **收盘日报**：交易日自动生成今日复盘 + 明日短线计划，可推送 Server酱/Webhook，支持删除重生成；未持有推荐不会自动挂卖出提醒，避免把研究观察误当成持仓指令
- ⏰ **提醒与待办**：到价/异动/均线/突破/放量条件提醒，叠加成本止盈、成本止损、移动止盈等持仓规则；Today 统一收件箱按需处理/仅知晓/已完成聚合提醒命中、复盘信号、逻辑卡到期，并支持稍后、同日静默、同股同类合并、来源筛选和批量操作
- 🧭 **提醒模板向导**：按模板、股票/持仓范围、核心参数和确认四步创建 11 类真实提醒；旧规则可无损回显，特殊组合保留专家模式
- 💼 **持仓管理**：多笔流水账本与加权成本/已实现盈亏、持仓期最高价与回撤、组合风控信号、推荐↔持仓血缘；统一持仓卖出风险评估按持仓逐笔结合成本、计划、峰值回撤、均线/ATR/行情状态输出正常/关注/复核/紧急/未知，并可发起精确 AI 复核
- 🧾 **数据导入**：自选、持仓与交易流水支持向导式导入、预览校验、幂等提交与失败回滚，导入结果可追溯
- 🎮 **模拟交易**：虚拟 10 万本金、真实行情成交与费税；指数 ETF 交易（免印花税费率）
- 🗂️ **研究辅助**：投资逻辑卡（失效条件+一键体检）、投资笔记、自选分组与研究阶段漏斗

**系统与管理**

- ⚙️ **LLM 配置**：多配置管理、OpenAI 兼容（`/v1/chat/completions` 与 `/v1/responses` 双端点）、测试连接、每用户次数配额熔断
- 🔄 **LLM 回退**：未配置 LLM 的用户可自动回退管理员指定配置（总闸+指定配置可控），后台任务共用系统默认 LLM

- 🖥️ **管理后台**：用户启停与配额、**LLM 调用审计**（全用户请求/响应明细，支持按 trace/run 关联筛选，90 天自动清理）、新闻采集配置、GitHub 凭证与注册开关、数据源同步日志
- 🩺 **数据源运维**：provider × capability × market 能力矩阵、健康滑窗、缺口日历、单能力探测、人工解冷与同步审计
- 🧭 **候选池透明度**：推荐结果保留来源、过滤、量化排名和 LLM 选择/剔除原因，便于复盘当前推荐为什么入池或落选
- 🗄️ **数据库迁移**：服务启动通过 GORM AutoMigrate 自动创建和变更表结构；Docker 重新构建并启动时会自动执行迁移，无需手工维护 SQL（生产仍应先备份并查看启动日志）

## 🚀 快速开始

### 源码运行（开发）

要求：Go ≥ 1.25，Node.js ≥ 20（实测 v24）。

```bash
# 后端（SQL_DSN=local 使用本地 SQLite，零外部依赖）
cd server
SQL_DSN=local go run .

# 前端（另开终端）
cd web
npm install
npm run dev
```

访问 `http://localhost:5173`，首次启动会引导创建管理员账号。

### Docker 部署（生产）

```bash
docker buildx build --platform linux/amd64 -t <你的镜像名>:tag --load .
docker push <你的镜像名>:tag
```

生产环境用 `deploy/docker-compose.example.yml` 为模板编排（MySQL + Redis + 应用），密钥经 `deploy/.env` 注入。完整流程（宝塔编排、反代与真实 IP、数据库自动迁移、备份恢复）见 [部署说明](docs/DEPLOYMENT.md)。

## ⚙️ 环境变量

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `SQL_DSN` | 是 | `local`/留空 = 本地 SQLite（开发）；MySQL DSN = 生产模式（触发密钥强校验） |
| `SESSION_SECRET` | 生产必填 | JWT 签名密钥，`openssl rand -base64 36` 生成；生产环境弱值拒绝启动 |
| `ENCRYPTION_KEY` | 生产必填 | 敏感字段加密密钥（LLM API Key 等）；**备份恢复须用同一密钥** |
| `PORT` | 否 | 监听端口，默认 `3000` |
| `SQLITE_PATH` | 否 | SQLite 文件路径（默认程序目录） |
| `REDIS_CONN_STRING` | 否 | Redis 连接串，缺省不启用缓存 |
| `ALLOWED_ORIGINS` | 否 | 生产 CORS 白名单，逗号分隔 |
| `TRUSTED_PROXIES` | 否 | 反代场景可信代理地址（如 `172.18.0.1`），不设则不信任代理头 |
| `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` | 否 | GitHub OAuth 首启种子，之后以管理后台配置为准 |
| `TUSHARE_TOKEN` | 否 | Tushare Pro token（分档按需启用） |
| `DEFAULT_MARKET` | 否 | 默认市场，当前仅 `cn` |
| `DEBUG` | 否 | 调试日志，默认 `false` |

## 🔐 安全特性

- **LLM API Key 加密落库**：AES-256-GCM 加密存储，模型字段 `json:"-"` 永不回显给前端；推送通道密钥、GitHub secret 同等处理
- **JWT 双 token**：短期 access + 轮换 refresh，`TokenVersion` 支持单用户强制全端登出（禁用用户即时生效）
- **SSRF 防护**：LLM Base URL 与 Webhook 仅放行公网 http/https，内网地址仅管理员（或管理员所有的回退配置）可用
- **认证限流**：登录/注册按 IP 限流，反代场景配 `TRUSTED_PROXIES` 后按真实客户端 IP
- **生产密钥 fail-fast**：连接真实 MySQL 时占位/弱密钥直接拒绝启动
- **调用审计**：全用户 LLM 调用明细（含请求/响应全文）仅管理员可见，90 天自动清理
- 备份恢复依赖同一 `ENCRYPTION_KEY`，密钥丢失则密文字段需重新录入
